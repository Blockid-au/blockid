## Findings → fixed

1. **Doubled brand suffix everywhere in scope** — pages appended `· BlockID.au` / catalogue titles ended `| BlockID.au` on top of the root template. Fixed: suffix stripped from `en.json`/`vi.json` `meta.compare.*`, `meta.solutions.{advisor,investor,accelerator}.*`, `meta.funding.*`; funding pages pass bare cores; `renderedTitle()` in tests pins the rendered form. (`web/src/lib/seo/page-meta.ts`)
2. **OG/Twitter image dropped on every page** — Next replaces, never merges, a page-level `openGraph`/`twitter` object. Fixed: `pageMetadata()` always carries `OG_IMAGE` (`/opengraph-image`, 1200×630) and `summary_large_image`; every audited page now builds metadata through it.
3. **Detail descriptions = bare `summary` (31–122 chars)** — fixed with `grantDescription()` / `programDescription()` composing name + noun + provider + state, funding terms, status/close date, summary, and the "eligibility, evidence, official link" sentence into 140–160 (`fitDescription`). Tested over all 252 rows.
4. **Detail titles up to 100+ chars, no state** — fixed with `grantTitle()` / `programTitle()` (see keyword map). Uniqueness across all 252 asserted in `seo.test.ts`.
5. **Relative canonicals on funding pages** — now absolute `https://blockid.au/…`.
6. **Invisible layout-scope `FAQPage` + Home-only `BreadcrumbList`** in `(marketing)/layout.tsx` — violated the visible-content rule and doubled the FAQPage on `/compare` and `/solutions/*`. Removed; `Product` kept. `SolutionsPageShell` now emits its own `FAQJsonLd` (prices filled the same way the visible `<dl>` is) + `BreadcrumbListJsonLd` (EN and VI paths).
7. **No JSON-LD validator** — added `validateJsonLd()` + `extractJsonLd()` (`web/src/lib/seo/structured-data.ts`): `@context`/`@type`, nested `@type`, no `undefined`/`null`/empty values, ordered `position`s, `ItemList.numberOfItems`, `FAQPage` shape, `Article.headline` ≤ 110. Every seed row's `GovernmentService`/`Service`/`Event` object and every rendered block on every audited page is asserted valid. `stripUndefined` in `directory.ts` is now deep (grant `offers.priceSpecification.minPrice: undefined` was leaking).
8. **Grant schema type** — university / private / RDC providers were `GovernmentService` + `GovernmentOrganization`; now plain `Service` + `Organization` for those levels (`GOVERNMENT_LEVELS`).
9. **Missing `BreadcrumbList`** on `/funding` (landing), `/funding/report/demo`, `/docs/unlocks`, `/solutions/*` — added; `FUNDING_CRUMBS` centralises the trails. `/docs/unlocks` also gets a `WebPage` block.
10. **Capital → city grouping not in copy** — `CAPITAL_SATELLITES` (seed-map, every entry round-trips through `capitalForCity`, `"regional queensland"` alias added) drives a visible coverage sentence + the meta description on each capital page (Sydney→Wollongong, Melbourne→Geelong, Brisbane→Gold Coast/Sunshine Coast/Regional Queensland, Hobart→Launceston).
11. **"`<state>` startup grants" had no landing URL** — `/funding/grants?state=NSW` (state-only filter) now self-canonicalises with its own title/H1/description/ItemList name/breadcrumb and a sibling-state nav; any other filter combination canonicalises to `/funding/grants`. 9 state views added to the sitemap.
12. **Internal linking** — `FundingGuides` strip (directory + capital pages) and compact list (detail asides) link the R&D/ESIC/grants/accelerators insight articles (slugs pinned against `content/insights/manifest.json`; RDTI/ESIC rows lead with their own guide); detail pages link the state view, the capital page / programs directory and the demo; the demo links both directories; capital pages link their state's grants view.
13. **Sitemap** — `/vi/funding` entry + hreflang pair on both; index/capital/state `lastModified` = newest child `last_verified_at`; test now loads the real seeds and asserts 53 + 199 + 9 + 9 + 5 funding URLs, per-row `lastModified`, no duplicate URLs, and the other audited static pages.
14. **H1s** — programs index / capital H1s carry "accelerators and incubators"; `/docs/unlocks` H1 leads with the outcome; every audited page asserts exactly one `<h1>`.
15. **404 shells** — `robots: { index: false, follow: false }` (was `{ index: false }`).
16. `/vi/funding` — title 40 chars, description 159, `vi_VN` locale, OG image; VI compare/solutions titles shortened and de-suffixed (`/vi/*` bodies untouched).

## Deferred (with reason)

- **`/funding/grants/state/[state]` as a path route** — the query-string view (`?state=NSW`) is self-canonical and in the sitemap, which is enough for indexing; a path route would need a redirect matrix for the existing chip links. Revisit once Search Console shows impressions for the state queries.
- **Brand suffix on other marketing pages** (`/pricing` = `Pricing — BlockID.au | BlockID.au`, `meta.solutions.founder|vnSme.title` still end `| BlockID.au`) — outside the S8-A page list; same one-line fix via `pageMetadata()` / catalogue edit. Recommend a follow-up sweep of `src/app/(marketing)/*` and `src/app/vi/*`.
- **`robots.txt` `Disallow: /funding/report/`** — the paid report is `noindex, nofollow` at the page; adding a robots block would stop Google from seeing the noindex on any URL it has already fetched. Left as is.
- **`FAQPage` on the funding directories** — no visible FAQ exists there; adding schema without content would repeat finding 6. Consider a short visible FAQ ("Is grant information free?", "What does A$3 buy?") on `/funding` in a later copy pass (D-3 strings in `copy.ts` untouched per brief).
- **Thin pages** — the `seo-content-au` skill's 800-word guardrail is not met by many program detail pages (short `summary`, few benefits). The data, not the template, is the limit; the refresh cron / admin patch path can lift `summary` and `benefits` per row.
- **VI twins for the directories** — no `/vi/funding/grants|programs` routes exist, so no hreflang is emitted there (correct); a VI mirror is a product decision, not an SEO fix.
