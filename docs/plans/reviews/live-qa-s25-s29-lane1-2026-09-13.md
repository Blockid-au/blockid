## Findings (ranked)

**F1 · P0 · Fundraise round creation has never worked on production** — `/workspace/fundraise` "Calculate Share Price" → `POST /api/fundraise` **500** "Failed to save fundraise round". Server log: `insert or update on table "fundraise_rounds" violates foreign key constraint "fundraise_rounds_account_id_fkey" … Key (account_id)=(<app_users.id>) is not present in table "svi_accounts"`. The table was created by `web/supabase/migrations/0043_missing_tables.sql:10` with `account_id uuid references svi_accounts(id)`, while `web/src/app/api/fundraise/route.ts:101,257` writes `scope.ownerUserId ?? user.id` (an `app_users.id`). Prod: `fundraise_rounds` count = 0 (ever); 0 of 70 `app_users` have an `svi_accounts` row with the same id; a second user hit the same error today at 13:01 UTC. Everything downstream in S26 (round page, progress bar, commitments, Open round + data-room attach, `fundraise_commitments`, investor follow-ups) is unreachable. Fix: repoint/drop the FK (a migration `alter table fundraise_rounds drop constraint fundraise_rounds_account_id_fkey; … references app_users(id) on delete cascade`), then re-run this lane's #12–#13. Repro: any logged-in founder with ≥1 shareholder, fill target/pre-money, click Calculate Share Price.

**F2 · P1 · "Connect Xero" dead-ends in a JSON 503** — `web/src/app/(app)/(founder)/workspace/revenue/revenue-client.tsx:887` links `/api/oauth/xero`; on production `XERO_CLIENT_ID` is unset so `web/src/app/api/oauth/xero/route.ts:34` returns `503 {"ok":false,"error":"Xero OAuth not configured"}` as the whole page. The S25-A scope (`offline_access accounting.reports.read`) could not be verified live. Either set the Xero app credentials or gate the button on the HEAD probe (the evidence page already does this) and show "Not configured yet".

**F3 · P1 · Valuation, share price, DRIP preview and listing readiness all run on a fabricated SVI of 100 when the account has no analysis** — `/api/share-price` returns `inputs.svi:100` → "A$1.0875 per share · SVI score only" for an account with `analyses:[]`; `/dashboard/valuation` hero shows A$535K / 60 % confidence / "SVI 100"; the DRIP preview prices reinvestment at A$1.09; listing readiness says "Computed from 2 cap-table holders at A$1.09 per share (current mid)". Same root as QA2 F4 (`web/src/app/api/valuation/vc/route.ts:126` `?? 100`), now propagated through `web/src/lib/valuation/share-price*` (source label is honest, the number is not). The certificate panel is the only surface that refuses (409 `no_svi_analysis`). Fix: return `ok:false, reason:"no_svi_analysis"` from the share-price resolver when no analysis exists and render the empty states.

**F4 · P2 · Workspace header clips its right-hand controls at 390 px** — on every workspace page the header action row measures 574 px; "Switch to dark mode" (x=420–450), "Notifications" (454–486) and "Sign out" (538–574) are outside the viewport with no horizontal scroll (the page itself stays 390 px wide). Screenshot `qa1/shot-mobile-_workspace_investors.png`. Wrap or collapse the header actions into the menu below `sm`.

**F5 · P2 · AI expense categoriser mislabels obvious lines with high confidence and no review flag** — "BLRGH CONSULTING INV 1002" −A$2,200 → `bank_fees`, confidence 0.8, `needsReview:false`, GST `input_taxed` (so it drops out of GST credits); "XYZQ WIDGETS PTY LTD 4471" −A$88 → `salaries_wages` 0.9. The preview copy promises unsure lines come back as "needs review"; the model is confidently wrong instead. Consider a keyword prior (CONSULTING/INV → professional_fees / contractors; PTY LTD merchant → not payroll) and a lower auto-accept threshold, or always flag AI rows on the first import. `web/src/app/api/expenses/categorise/route.ts`, `web/src/lib/expenses/`.

**F6 · P2 · Cloudflare-injected Google tag bootstrap is blocked by CSP on every page** — two inline scripts without a nonce (`(function(w,i,g){…('window','GTM-TRHH4MH2','google_tags_first_party')` and the `developer_id.dYzg1YT` GTM loader) are inserted at the edge ("Google tag gateway" / first-party mode) and fail `script-src 'nonce-…' 'strict-dynamic'` — one console error per page load. The app's own nonced snippet (`web/src/components/analytics/google-analytics.tsx`) does load and `/g/collect` fires, so analytics are not dark; but if CSP were ever relaxed both loaders would double-tag. Turn the Cloudflare tag gateway off (or let it own tagging and remove the in-app snippet).

**F7 · P2 · Data-room dependent S26/S29 checks cannot be exercised on the free allowance** — investor share link (`POST /api/investor-data-room` 409 `no_data_room`), the `auto_follow_up` checkbox, the clean-room "proven by the data room" rows and the NDA-toggle flip all require a generated room (3 credits) — a founder with the 3-credit welcome grant who spends anything first can never get there, and the round "Open" flow silently opens without a room. Consider making the first data-room compile included on Growth (the PDF exports already are) or a 1-credit "skeleton room".

**F8 · P2 · Free founder is dead-ended in the fundraise wizard** — with no shareholders the wizard answers "No shareholders found. Set up a cap table first." but `/workspace/cap-table` is Growth-only and the message has no link or plan hint (`web/src/app/(app)/(founder)/workspace/fundraise/fundraise-client.tsx`). Route the message to `/pricing?feature=cap_table.write` or hide the wizard behind the same gate.

**F9 · P3 · Listing readiness / clean room redirect to `/pricing?from=…` without `feature=`** (cap-table and data-room pass `feature=cap_table.write` / `data_room.access`), so the pricing page cannot highlight the plan that unlocks them (`requireTierForPage({ minTier: "growth" })` in both pages).

**F13 · P3 · On-chain panel: the "execution not enabled" wording is only reachable through a tooltip** — `chain-reconcile-panel.tsx:150-156` puts "on-chain execution needs a server signing key — not enabled yet" in the button `title` (and only when `pushable > 0`); the visible button says "Push register to chain". **F15 · P3 · Editor on a Growth owner's project is plan-gated by their own plan** — the Free-plan editor member is bounced from `/workspace/clean-room` (and by the same rule listing readiness / cap table) to `/pricing`, while the owner's Growth entitlement is what the data belongs to. `requireTierForPage` checks the caller's plan only.
