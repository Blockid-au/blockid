### Verified clean (no finding)

- **Audit override** — `auditAction()` only accepts `<domain>.<verb>` strings from handler code; `ctx.action` is set inside the ALS store, never from body/query. `PATCH /api/fundraise/[roundId]` records `fundraise.round.closed` only after the update lands.
- **Board resolutions money path** — regenerate charges once (`cost` only when `!existing || regenerate` and not included), spend runs before `issueResolution`, `supersede_conflict` / `insert_failed` / concurrent `existing` all refund; superseded PDFs (`?version=n`) are free GETs, editor+, 404 on unknown/out-of-range versions. 0361 partial unique index admits one current row; restore-on-failure puts the old row back.
- **ESS annex** — every fact is `null` unless stored; `discount`/`holding`/`ownership`/`resident` are always `not_confirmed`; `ESS_NOT_SAFE_HARBOUR_SENTENCE` is rendered verbatim on the methods page and pinned by two suites; instrument name is the real one (*Income Tax Assessment (Methods for Valuing Unlisted Shares) Approval 2015*); s 83A-33(2)–(6) and s 83A-45(4)–(6) cites agree between annex, checker and qualifying-tests; age row is re-stamped at issue.
- **On-chain read-back** — `chainRpcUrl()` = `EVM_RPC_URL` or the fixed default; token address only from the project's `blockchain_sync_config` row and regex-checked; holder discovery capped at 2 000 addresses, one bounded batch; `ChainUnreachableError` → status `unreachable`, never drift. `reconcileCapTable` drift / unknown / missing (`zero_balance`, `no_wallet`) / zero-share rows all exercised by the suite. Reconciliation rows are project-scoped (FK CASCADE, owner RLS); route keys on `scope.ownerUserId`.
- **Chain-reconcile cron** — `isCronAuthorised`, `?dry=1` lists candidates with no RPC, no insert, no notification; drift notification throttled 7 days per project.
- **Order book engine** — price-time priority (price, then `seq`), partial fills rest, sells capped at position − resting, self-trade filtered, held sells excluded from matching; `priceDiscovery` returns finite numbers or null (fully diluted = issued + ESOP pool).
- **Sector multiples** — only `status='approved'` rows with `effective_from <= at` and a sane band are consulted (latest effective date, then latest approval); static table otherwise. Approve/reject use a status-conditional UPDATE (no double-win) and call `invalidateSectorMultiplesCache()`; the four consumer routes `await primeSectorMultiples()` first, so the admin sees the new value on the next request (multi-worker deployments fall back to the 10-minute TTL). Cron proposals are gated by `validateCandidate`: sector in the source's list, 0 < low ≤ mid ≤ high ≤ 200, excerpt 20–500 chars, **verbatim substring** of the text the model saw, and the excerpt must contain one of the numbers. The five source URLs are real public pages (SaaS Capital, Aventis, Damodaran psdata, BVP cloud index, Meritech comps). Admin-typed `source_url` must be http(s) on a dotted host; the excerpt renders through React (no `dangerouslySetInnerHTML`). 0369 adds CHECKs mirroring every rule + a partial unique index on open proposals.
- **AEST business days** — `addBusinessDays` steps 24 h in UTC and tests the weekday in `Australia/Sydney` via `Intl`, so AEST/AEDT are both handled; suite covers a Saturday-morning-AEST view.
- **Migrations** — 0361/0365/0366/0367/0369 idempotent (`IF NOT EXISTS`, `DROP POLICY IF EXISTS`, guarded constraints), RLS on every new table, `secondary_sim_orders.user_id → app_users(id) CASCADE`, `sector_multiples_overrides.approved_by → app_users(id) SET NULL`, `secondary_sim_trades.{buy,sell}_order_id` SET NULL. 0371 = 0370 + exactly one VALUES row (`secondary_sim_orders.user_id delete`) — verified by diff; erasure-map suite pins 128 entries against 0371.
