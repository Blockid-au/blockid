## Findings

### P1-1 — `POST /api/fundraise` always 500: FK `fundraise_rounds.account_id → svi_accounts(id)` vs route writing `app_users.id` (S26-A rounds/commitments/activate dead in prod)
`src/app/api/fundraise/route.ts:101,257` inserts `account_id: scope?.ownerUserId ?? user.id` (an `app_users.id`); migration `supabase/migrations/0043_missing_tables.sql:10` created the live table with `account_id uuid references svi_accounts(id) on delete cascade` (0030 had no FK). Prod log: `[fundraise] insert error 23503 Key (account_id)=(9902f68c-…) is not present in table "svi_accounts"`. `svi_accounts.id` never equals an `app_users.id` (0 of 70 users), so **no round has ever been saved** (`select count(*) from fundraise_rounds` = 0) and every dependent S26-A surface — commitments, `[roundId]/activate` + the data-room attach, follow-ups on commitments, `/workspace/fundraise/[roundId]` — is unreachable. Also a 500-not-4xx contract break.
Repro (Growth account with ≥1 shareholder): `curl -X POST https://blockid.au/api/fundraise -H 'Cookie: blockid_session=…' -H 'Content-Type: application/json' -d '{"roundName":"Seed","targetAmount":500000,"preMoneyValuation":4000000,"instrumentType":"safe"}'` → `500 {"ok":false,"error":"Failed to save fundraise round"}`.
Fix: migration `alter table fundraise_rounds drop constraint fundraise_rounds_account_id_fkey; … add constraint … foreign key (account_id) references app_users(id) on delete cascade` (mirrors `fundraise_commitments.created_by`, and `shareholders.account_id` which the same route already reads by user id), or resolve the `svi_accounts` id via `findSVIAccountWithFallback` before the insert. Add the S26-A round test that inserts against the real schema.

### P1-2 — Account erasure leaves the cap-table / dividend register behind (`shareholders`, `share_classes`, `share_transactions`, `dividend_records`)
After `erase-account.mjs --write` on the member account (tombstone written, 67 deletes incl. 60 `secondary_sim_orders`, project cascade removed investor_contacts / bank_transactions / listing_profiles / clean_room_checklists / secondary_sim_settings), the generic sweep (`every table with account_id|user_id|created_by … in (erased ids)`) still found: `shareholders.account_id` ×1 (**name + email of a third party**), `share_classes` ×1, `share_transactions` ×1, `dividend_records.account_id` ×1 (**`payouts` JSON with shareholder names and amounts**). These tables are keyed by `account_id` = `app_users.id` **without an FK** and are absent from `src/lib/privacy/erasure-map.ts` (0348 + 0351/0356/0368/0370/0371 never added them). `dividend_records.project_id` is also left NULL by `src/app/api/dividends/route.ts:173-180`, so the project cascade cannot catch it either. Only `app_user_audit_log` / `audit_events` / `credit_transactions` survivors are by design (anonymised). Prod today: 29 `shareholders` rows, 1 of them (ours) orphaned — **I deleted the four QA rows by hand** afterwards (`delete … where account_id='9902f68c…'`).
Fix: add `shareholders`, `share_classes`, `share_transactions`, `shares_held` (via shareholder), `dividend_records`, `esop_pool`/grants, `drip_elections` (project-keyed, ok) to `erasure-map.ts` as `account_id`/`user_id` deletes and regenerate the RPC (next `03xx_erase_account_*` migration); set `project_id` on dividend inserts.

### P3-a — Admin sector-multiples routes use a non-standard 401 body
`/api/admin/sector-multiples` GET/POST and `[id]/approve|reject` answer `401 {"ok":false,"reason":"no_user"}` (and `403 {"reason":"not_admin"}`) instead of `{ok:false,error:"unauthorized"}` — the shared `require-admin` shape. Cosmetic; clients matching on `error` will show a blank message.

### P3-b — `GET /api/board-resolutions/[kind]/[recordId]` answers 200 `resolution:null` for a record outside the project
`src/app/api/board-resolutions/[kind]/[recordId]/route.ts:190-210` only uuid-checks `recordId` and lists versions by `(kind, recordId, projectId)`; a foreign esop / share-issue / dividend id and a random uuid all get `200 {resolution:null, versions:[], stale:false}` while POST, `/pdf` and the docs say 404. No data returned and not an oracle (random == foreign), so contract-only. Fix: `loadResolutionInputs` first → 404 when null.

### P3-c — Sandbox 429 body lacks `sandbox:true` + notice
The 60/min `place` limiter returns the shared `enforceRateLimit` body (`src/lib/rate-limit.ts:255`) — the only `/api/secondary/sim/orders` response without the sandbox marker the route header promises on "every response". Spread `SANDBOX` into the limiter response in the route.

### P3-d — Included previews return `balance:null` and `creditNote:"Charged to your credits."`
When `included:true` (Growth), listing PDF / categorise / statements / board-resolution previews carry `balance:null` while the free path carries the number; the `creditNote` still reads "Charged to your credits." with `cost:0`. Contract says `cost, balance, included` consistently. Return the balance (it is one `getCreditBalance`) and an "Included with Growth" note when `cost === 0`.

### P3-e — `GET /api/dividends/tax-statements` names the listed price `cost` (2) while the POST preview uses `cost` (0 when included) + `listedCost`
Same number, different key semantics between the two verbs; the panel must not show "2 credits" to an included user off the GET.

### P3-f — `/api/status` anon payload only partially trimmed (QA4 P2-f residual)
Gone: `oauth_tokens_sealed`, the `ga4_events.missing` list. Still public: `slo.uptime_pct_24h`, per-service status incl. `audit_chain`/`ga4`, `last_deploy {ts, gates_passed, gates_expected}`. Not exploitable; trim to `{ok, version}` for anon as the ticket asked.

### P3-g — `sector-multiples-refresh?dry=1&extract=1` exceeds the Cloudflare 100 s edge timeout (504) on 2 of 3 public-edge calls
The route allows `maxDuration 300`; run 2 took 103 s locally (5 sources × model). The scheduled run is unaffected (`scripts/cron-runner.sh:62` → `http://127.0.0.1:4001`), but the "manual `?dry=1&extract=1` check" the route header documents cannot be done through `https://blockid.au`. Document the local path, or cap per-source model time.

### P3-h — Extraction yield ≈0: 3/5 allow-listed sources come back `ai_unparseable`
The free model replies with reasoning prose ("We need to extract…") or a truncated array, so `parseCandidates` (src/lib/valuation/multiples-refresh.ts:159) returns null; run 1 proposed 1 row (bvp), run 2 proposed 0. The quarterly cron will mostly propose nothing. Ask for `json_object`/strict-JSON mode, raise `max_tokens`, or retry with the next model on `ai_unparseable`.
