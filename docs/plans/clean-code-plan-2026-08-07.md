# Clean-Code Plan — Consolidate `digest-snapshot-per-*.ts` stubs

## Problem

`web/src/lib/reseller/digest-snapshot-per-*.ts` currently holds **412 near-identical files** (206 `.ts` + 206 colocated `.test.ts` — plus some accessories) auto-generated by the P11.4xx loop. Every file follows the same 20-line skeleton:

```ts
export interface DigestSnapshotPer<Metric>Row { ... }
export function digestSnapshotPer<Metric>(rows: Row[]): DigestSnapshotPer<Metric>Row[] { ... }
```

They ARE wired (792 imports across the app — cron/weekly-digest, admin dashboards, reseller emails) so **we cannot delete**. But the current shape means every new metric = one PR × one file × one test × one registry line.

## Why fix

- **Cognitive load** — anyone reviewing `web/src/lib/reseller/` sees 412 files with 4-char name deltas.
- **CI cost** — each file is a separate vitest module (import overhead ≈ 200-500ms × 206 tests = ~1-2 min of the 82s test suite budget).
- **Loop pollution risk** — the auto-generator can drift silently; a registry-driven design catches "metric X missing from spec" statically.
- **Future onboarding** — a new agent grepping for reseller code drowns in the noise.

**We can NOT touch** — the loop is actively adding new PT*NM entries (P11.471 landed 10:20 UTC, `M_108 PTOCNM` just wired). Any consolidation MUST co-exist with the loop until the loop is retired.

## Proposed design

Replace the 412 files with **one registry-driven module**:

```
web/src/lib/reseller/digest-snapshots/
  ├─ registry.ts               ← array of { slug, kind, dimension, fn } entries
  ├─ compute.ts                ← generic snapshot compute() — takes a metric fn
  ├─ metrics/
  │   ├─ moment.ts             ← mean, median, stdev (1 file for 30+ variants)
  │   ├─ percentile.ts         ← p10, p50, p90, p95, p99 (1 file)
  │   ├─ dispersion.ts         ← range, IQR, PT*NM peak-to-N-mean family (1 file)
  │   └─ streak.ts             ← direction-streak, momentum (1 file)
  └─ index.ts                  ← barrel re-export so 792 existing imports keep working
```

- Each existing `digest-snapshot-per-X.ts` becomes a **1-line re-export** from the registry:
  ```ts
  export { digestSnapshotPerX } from "./digest-snapshots";
  ```
- Colocated tests fold into `digest-snapshots/*.test.ts` — one per metric family, ~200 tests total (was 206 files × 30-50 cases).
- The auto-loop keeps generating registry entries (add to `registry.ts`) — no more per-file scaffolding.

## Phased execution

### P0 — Freeze the loop (30 min, human)
- Add `CLEAN_CODE_LOOP=on` gate to `scripts/cron/reseller-goal-loop.mjs` so the auto-generator pauses while consolidation happens.
- Loop resumes AFTER the registry module ships.

### P1 — Ship the registry module (2 h, agent)
- New folder `web/src/lib/reseller/digest-snapshots/`.
- `compute.ts`, `metrics/moment.ts`, `metrics/percentile.ts`, `metrics/dispersion.ts`, `metrics/streak.ts`.
- `registry.ts` seeded from the 206 existing metric slugs (parse file names → entries).
- `index.ts` barrel with named re-exports matching the current 792 consumer signatures **exactly** — no consumer edits.
- Colocated `digest-snapshots/*.test.ts` covering each family + registry round-trip.

### P2 — Migrate each existing file to a 1-line re-export (4 h, agent)
- Script iterates over the 206 `.ts` files, rewrites each to `export { X } from "./digest-snapshots";`.
- Deletes each `.test.ts` (family test suite covers them all).
- After each 50-file batch: `npx tsc --noEmit && npm test` — must be green before the next batch.

### P3 — Delete the 1-line re-export shims (2 h, agent)
- Grep every consumer, rewrite `import X from "./digest-snapshot-per-X"` → `import { X } from "@/lib/reseller/digest-snapshots"`.
- Now the 206 stub `.ts` files are dead — delete them.

### P4 — Unfreeze the loop with registry-write mode (1 h, human)
- Reseller loop generator now appends to `registry.ts` instead of creating a new file.
- Re-enable cron.

## Acceptance gates

- `find web/src/lib/reseller -maxdepth 1 -name 'digest-snapshot-per-*.ts' | wc -l` → **0**

- `npm test` — 20 955+ tests pass (no regression); test count MAY drop by ~5-8k as duplicate coverage collapses into family suites.
- `npx tsc --noEmit` clean.
- All 3 goal loops (atlassian, reseller, ux-ia) continue to green ticks through the migration.

## Non-goals

- Do NOT touch the metric mathematics — behaviour must be byte-identical.
- Do NOT change the weekly-digest email format.
- Do NOT deprecate the `PT*NM` naming — legacy identifiers stay.
- Do NOT rewrite the reseller loop itself — only the OUTPUT shape.
