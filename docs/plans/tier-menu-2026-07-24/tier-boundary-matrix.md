# Tier Boundary Matrix — 2026-07-24 review artefact

**Owner:** CFO agent.
**Source of truth:** `web/src/lib/entitlements/tier-ladder.ts` (this file is
generated by hand from the ladder — regenerate any time a tier row moves).
**Sign-off:** founder review required before ANY dollar-amount change ships.

Prices below are **frozen**. This matrix aligns feature membership only.

## Rule

**One headline unlock per boundary.** Every upgrade must solve the *next
growth-phase problem*. If a proposed boundary cannot be summarised in one
sentence a founder recognises as "the reason I would pay", the boundary is
wrong — reshape the SKUs, do not smuggle three unrelated features in.

## Guardrails

1. **Price freeze.** Any diff that touches `monthly_aud`, `annual_aud`,
   `trial_days` or `most_popular` in `plans-v2.ts`, `plans.csv`,
   `plans.generated.ts`, the Supabase `plans` table, or `stripe-seed.json`
   MUST carry an explicit `pricing-change-approved` review label.
2. **Ladder monotonicity.** `tier-ladder.test.ts` fails the build if any
   supportingUnlocks[N] loses a feature present at rank N-1 within the same
   segment.
3. **No orphan features.** The union of every entry's `supportingUnlocks`
   is required to be a superset of every `required_feature` in
   `FEATURE_GATES` AND every feature key across `LEGACY_FEATURE_FALLBACK`.
4. **Unique headline copy.** No two entries share a `headlineUnlock` string
   — the pricing page and 402 upgrade payload rely on that uniqueness for
   deep-link scroll targeting.
5. **`reseller_admin` never on the marketing surface.** It is in
   `TIER_LADDER_BY_ID` but excluded from every `*_LADDER` array and flagged
   `hiddenFromPublic:true`. Regressions caught by the ladder test.
6. **Legacy plan IDs still resolve.** `free`, `founding50`, `growth`,
   `growth_annual` must each map through `PLAN_ID_TO_TIER` to a founder
   ladder entry so grandfathered customers keep their headline copy.
