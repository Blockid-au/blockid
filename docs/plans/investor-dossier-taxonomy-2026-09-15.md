## 2. S-D3 detail (G13-W5-D3)

### Seats & consensus (E4.5, F1–F4)
- `lib/investor/organisations.ts` — the personal org from S-T2 **is** the team. Seat limit = `plans.usage_limits.seats` (**Scout 1 · Firm 3 · Program 5**; Fund 10 · Cohort 25 = 5 · Cohort 100 = 15 · Enterprise / VC Enterprise unlimited; tier fallback when the plans row is unreadable). `inviteMember` counts members + open invites, answers **402 `seat_limit`** with the plan message and the upgrade hint (no Stripe change), sends the magic link (`/auth/login?next=/workspace/investor/team?invite=<token>`, 14-day token, one open invite per (org, email); a re-send refreshes the token). `acceptInvite` requires the signed-in user's email to match; `removeSeat` is owner-only and never the owner. New page `/workspace/investor/team` (+ `GET/POST/DELETE /api/investor/organisation`, `POST /api/investor/organisation/accept`).
- **Access (F1):** `resolveDossierAccess` admits a same-org seat as an assessor of their own seat (one extra membership read on the miss path); `isEvaluatorUser` accepts an invited seat without a persona or plan (the owner's plan carries the entitlement); assessment writes stamp `org_id` with the seat's acting org (the first org they do not own, else their personal org).
- **Consensus rule (F2, Appendix 2):** computed on read, never stored. Every seat's CURRENT version; **submitted rows only** enter the numbers: median rating per dimension, decision tally, mean conviction, `aggregate` = majority (tie → `split`), `disagreement` = dimensions whose seat ratings span ≥ 2 ("Discuss" marker). Header chip "Firm consensus (submitted/seats)" appears from 2 seats; a single personal seat shows the invite prompt. Other seats' `private_notes` are never returned (`toSeatVisible`); the founder never receives the consensus object at all (`DossierView.consensus = null`).

### IC memo / one-pager (E4.6, S6, F3)
- `lib/evaluations/ic-reports.ts` + `lib/pdf/ic-memo-pdf.tsx` + `GET/POST /api/evaluations/[id]/ic-report`. `ic_reports` **did not exist** in production (the BA spec assumed the deferred portal-core file) → created in **0403** with FKs to `evaluations` / `projects` / `svi_snapshots` / `investor_organisations` only (`user_id`, `generated_by`, `assessment_id` bare — erasure-map rule). `sections` freezes the decision record {summary, svi_table, valuation, thesis_fit, risks, questions, decision, seats, consensus}; the PDF is re-rendered from the persisted snapshot visuals + sections on GET (never stored as bytes).
- **Kinds:** Scout → `one_page` only (**exactly 1 page**, pinned); Firm / Program → `memo` (**2–4 pages**: cover numbers + radar twin + weighted table + decision record · valuation range bars + methods + risks / questions · seat views + consensus). **F3:** the weighted-score column always prints; the raw **Weight** column only for Program and above (`weights_shown` recorded on the row). Footer on every page: "Prepared with BlockID.au · Auschain PTY LTD · not financial advice". Audit `ic_report.exported`. Header action "Export IC" + the block-6 button.

### Cohort decisions (E4.7, P1 / P2 / P4)
- `CohortRow` gains `decision · conviction · thesisFitPct · assessmentStatus` from the **batch owner's** latest `evaluation_assessments` row (`lib/evaluations/cohort-decisions.ts`); sortable columns (decision sorts proceed > track > pass, undecided last); CSV gains `Decision, Conviction, Thesis fit %, Assessment status` after Top gap.
- **Bulk set:** select rows → "Set decision (draft)" → `POST | PATCH /api/evaluations/batch/[id]/assessments` `{evaluation_ids, decision?, conviction?}` → one DRAFT per owned row through the S-D2 upsert (batch snapshot stamped; nothing is submitted — submit still needs conviction on the dossier), foreign ids skipped, ONE `assessment.bulk_set` audit row with the id list.
- **LP report (P4):** `summariseQuarterly().pipeline` = pass / track / proceed / undecided from **submitted** decisions only; the sponsor / LP HTML has a "Pipeline" tile row and the per-startup one-liner carries "Proceed 4/5" / "Track (draft) 3/5". Rubric weights stay display-only (P3 unchanged).

### Block 3 — evidence & consent (E3.4)
- `lib/mentor/access-tiers.ts` `DOSSIER_FIELD_ALLOW_LIST` — exactly the §A.3 table (attributed_only: phase · KPI bands · evidence counts; reports_shared: + full report · items · source kind · freshness · connector freshness · public URLs; full_mentor: + document links · data-room index · cap-table summary · exit readiness · founder notes). `dossier/evidence-block.tsx` renders the item list grouped by dimension with the `EVIDENCE_BONUS` ladder label + freshness, the "what this tier shows" legend, and the request-upgrade CTA: unclaimed → the existing claim link; claimed → `access_requested` notification to the founder (24 h throttle per tier), audit `consent.requested`.

### Block 6 — actions & audit trail (E3.6 / E3.7)
- `POST /api/evaluations/[id]/actions` (`lib/investor/actions.ts`): **watchlist** (writes `watchlist.project_id` + the listing ticker or a deterministic `PRJ-<8 hex>`; idempotent), **portfolio** "Mark as invested" (`investor_portfolio` upsert on (investor, project) with `startup_id` = project id and the new `project_id` FK; pre-0403 fallback), **intro** (Scout → mailto kept; Firm / Program on a claimed row at ≥ reports_shared → `investor_contacts` row on the **founder's** project, stage `contacted`, source `dossier_intro`, + `intro_requested` notification; below reports_shared → 422), **batch** (deep link `/workspace/evaluations?batch=<id>` preselects the row and opens the batch dialog — Program only). Audit trail list = the viewer's own `audit_events` rows on the evaluation (ids / enums only, never note bodies). `watchlist.project_id` (E3.7) verified present in production since 0392 (backfilled where the ticker resolves to one project).

### Founder side (E2.6)
