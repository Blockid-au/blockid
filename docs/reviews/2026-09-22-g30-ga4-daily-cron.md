# GA4 daily cron: scoped standalone reader

Scope is the existing scripts/cron/ga4-daily-pull.mjs job only. No schedule, application build, analytics property/account, notification channel or production data is changed by this source patch.

The cron accepts the existing service-account email/private-key pair and JSON credentials, including JSON-to-pair fallback and escaped key newlines. Numeric GA4_PROPERTY_ID / GA_PROPERTY_ID normalization follows the application reader. Explicit process env wins; existing root .env.local, web .env.local and web .env files supply missing values without printing them. Read-only layout inspection found the private production env at web/.env and no root .env.local, so pair support alone would not fix an unsourced cron. googleapis resolves from the existing web dependency installation; no package install is required.

All five actual collector requests—totals, pages, events, acquisition and seven-day trend—carry the exact case-insensitive blockid.au/www.blockid.au hostname filter. Snapshots include hostname_scope. Daily no-op detection requires the same date, property, one-day range and exact hostname scope; an older property-wide snapshot cannot suppress the new scoped observation. Existing historical lines are retained. This does not add concurrency locking or claim transactional uniqueness between simultaneous cron invocations.

`--dry-run --no-notify` previews configured status, date and hostname scope only: no Google calls, report/heartbeat writes or notifications. `--no-notify` is also accepted for a controlled real refresh; no mode has notification hooks. API/import failures use generic messages rather than logging raw Google exceptions. Actual writes in normal mode remain the existing local snapshot and cron-health files. The existing scheduled invocation remains valid.

Five offline node:test cases pass: credential/property parsing, env precedence, scoped duplicate detection, all five mocked collector requests with scoped output, and dry-run/no-notify options. Syntax and diff checks pass. Tests import only pure helpers; the actual cron entry was not executed, Google was not called, and no shared caches or credentials were changed. Root may run an explicit dry-run and controlled no-notify refresh only after integration and the in-flight BlockID build exits. No application rebuild is needed for these standalone ESM cron files.
