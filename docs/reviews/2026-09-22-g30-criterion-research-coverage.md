# Criterion research coverage and investor implication availability

This phase consumes existing data; it performs no new provider invocation or research. Inspection found that the structured findings reader already displays criterion assessments. The remaining contract gap was that criterion-specific research coverage and missing business-specific implications were not explicit next to the static diligence guidance.

`CriterionCard.researchCoverage` is an optional additive contract. The canonical pipeline projection attaches it from the same report's appendix.publicResearch, and BusinessFindings uses that same deterministic projection on read for older reports. The reader recalculates from actual appendix data rather than trusting stale optional metadata.

Only the market criterion currently has a matching structured public-source task. Status distinguishes no recorded task, not run, blocked, no source retrieved and recorded retrieved sources. Retrieval counts require found records with a SHA256 content fingerprint, retrieval timestamp and nonempty excerpt. Merely naming a URL, citing a deck, marking a criterion grounded or setting the task summary to found does not establish research completion. A source record remains publisher material, not independently verified evidence or proof of competitor relevance. The contract intentionally has no completed-research status.

Business-specific investor implication and market comparison remain explicitly not recorded/not assessed. No existing structured upstream field establishes either. The UI retains the current verdict, evidence and static investor diligence guidance and shows the coverage/availability distinction inside each criterion's existing disclosure in English and Vietnamese. This adds no extra top-level messages or credit charge.

Backward compatibility: old reports without the optional field still validate and render; no database migration is needed. Older readers can ignore the additive field. The pipeline writer adds it to newly projected canonical reports. No financial values, scores, quotes or company-specific conclusions are generated by this projection.

Focused verification covers old/deck-only reads, market-only matching, valid retrieval without verification claims, missing source despite found task summary, blocked retrieval, stale optional metadata, canonical report schema validation and consumed bilingual disclosure. Follow-up work remains substantive research qualification and evidence-linked company-specific implications; these markers make the current limitation visible without pretending that work is complete.

Validation: 20 focused tests passed across coverage/projection/findings readers, with Vitest cache disabled. Scoped TypeScript for the new projection and consuming UI passed with incremental output disabled and a private configuration. No paid or production runs were made.
