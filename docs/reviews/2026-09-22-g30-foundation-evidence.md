## Integration findings and disposition

Independent reviewer `/root/release_safety` traced an upstream billing-admission path: `pitchdeck-analyze-client.tsx` calls `/api/pitchdeck/analyze`, which attempts spending before returning dimensions; the client forwards them with deck text to the stream. With 1–7 dimensions, downstream rejection would occur after that earlier attempt. Candidate `cf3845812` now rejects unsupported partial/blank deck requests before credit checks or spending, and the UI asks for explicit full-scope selection and cost review. Integrated deck-admission/stream/runner checks passed **58 tests / 3 files** (`/tmp/g30-deck-admission-integration-tests.log`).

Further read-only tracing found the existing `pitchdeck_speculative` feature absent from both web and billing-service price tables: metadata `totalCost` does not set the debit amount. Thus the current source predicts paid-gap requests fail `spend_failed`, not proof that a production debit occurred. Normal deck streaming omits tier and therefore adds no second debit. Correct authoritative total pricing, affordability, atomic/idempotent spending and failure recovery remain B02/B03 work; mocked endpoint tests do not certify a successful paid purchase.

A second review finding was resolved in `4a086efcd`: a section retry must retain a failed full-document save warning and keep old-snapshot actions hidden. Successful partial generation does not repair durable saving. The rendered retry/restore cases pass; actual browser acceptance remains pending.
