# G33 status aggregate correction — 24/09/2026

Status: implemented in source and focused tests; **not deployed or live-accepted**.

`web/src/app/api/status/route.ts` previously assigned both public and trusted
`ok` from service health and resource SLOs alone. A report-quality `down` verdict
could therefore coexist with `ok: true`. Both payloads now use the same aggregate:
services healthy, SLOs within thresholds, and report-quality status not `down`.

The endpoint retains HTTP 200, public cache headers and trusted `no-store`.
Consumers must inspect the JSON `ok` field; an HTTP-only monitor cannot detect
this product outage. `watch` stays advisory and `missing` stays unknown rather
than being reclassified as an outage.

The quality reducer is unchanged. Its `degradedShare` is the fraction of runs
with **any** degraded sections, not the fraction that produced no report.
`noReportRuns` counts the latter. Current `down` semantics are either at least
two no-report runs comprising at least half the window, or the latest two
runs both producing no report. This patch does not silently change those
thresholds or claim their original plan discrepancy has been resolved.

Regression fixtures cover healthy infrastructure with report outage on both
audiences, the historical-shape `15/27 = 0.56` partial-degradation window with
only `3/27` no-report runs (`watch`), and missing telemetry. Existing route tests
continue to cover resource breaches, services, redaction and response contracts.

Validation command: `cd web && npx vitest run src/app/api/status/route.test.ts`.
Result: **122 tests passed** (including four new regression cases).
No inference, deploy, external notification or production write is part of this change.
