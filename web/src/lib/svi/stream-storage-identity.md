# F03: input-specific local stream restore

The stream session is mounted only after SHA-256 identifies the complete received input and scope. No trimming or prefix truncation is used. The existing useAuthUser hook resolves `/api/auth/me` before restore; the key binds that authenticated user ID, project, received-deck versus stored-project mode, effective report tier and locale. The current component/endpoint contract is free/en; this change neither adds paid selection nor claims Vietnamese report generation. The helper accepts explicit scope values for future reviewed routing changes.

Changing the deck or project hides the old session immediately, cancels stale identity resolution and mounts fresh state. A completed matching result may restore without starting another automatic analysis or re-firing the parent completion/save callback; the explicit rerun action remains. Intake text stays in the parent's props throughout hashing and is forwarded intact. No raw text appears in storage keys. Lack of WebCrypto, a resolved signed-in identity or a stable project disables result storage/restore but still mounts the intake/session. Old project-only keys and other input keys are ignored, not deleted. Existing explicit reset removes only the currently scoped result entry.

The 30-minute result TTL remains, with future/invalid dates rejected. Final projection and existing saved/failed-save metadata travel with the scoped result. Async cancellation is tested so a late hash for deck A cannot restore A after deck B arrives.

User-specific keys prevent another resolved user from restoring this result, but this is not immutable backend input identity, durable save proof, authentication of local contents or project authorization. The shared auth hook resolves on mount; continuous session/permission revalidation remains outside this change. A stored-project run without deck text still cannot detect changed server inputs until the backend supplies an input revision; its identity remains project plus effective tier/locale. Parent intake recovery remains the parent's responsibility; this module does not introduce a second copy of private source text. No database, server cache schema or provider request is changed.

Reader audit for the preceding F02 cache metadata: the active report runner explicitly reads metadata on the first existing dim_results entry; route.legacy.ts explicitly selects known dimension fields while replaying, ignoring additional keys. No extra array element is added. No other runtime cache readers were found in web/src, web/scripts or scripts (privacy erasure and version comments are not readers).
