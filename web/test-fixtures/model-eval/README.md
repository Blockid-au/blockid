# Model-eval golden set (G35 A2, pricing v5 §7.4)

Generated by `node scripts/ai/build-model-eval-fixtures.mjs` (deterministic;
`--check` fails when the files drift). **Synthetic only** — fictional
companies and seeded figures; the chat context quotes public Australian
program facts (ATO ESIC, business.gov.au R&DTI). No customer data: this repo
is public.

| Task | dev | held-out | EN / VI | Notes |
|---|---|---|---|---|
| report_chapter | 40 | 20 | 50/50 | ~20 % data-poor cases (no figures to cite) |
| ceo_synthesis | 40 | 20 | 50/50 | chapter verdicts carry `[ev:]` markers |
| grounding_judge | 40 | 20 | 50/50 | 5 claims each: 2 supported, 2 invented figures (critical), 1 unknown id |
| extraction | 40 | 20 | 50/50 | absent fields expected `null` (fabricating one is critical) |
| classify | 40 | 20 | 50/50 | 8 sectors × 4 stages |
| translation | 40 | 20 | EN→VI / VI→EN | figures, `[ev:]` markers, BlockID / SVI must survive verbatim |
| chat | 40 | 20 | 50/50 | includes "not in context" questions; no-advice guard |
| vision | 24 | 12 | 50/50 | **smaller on purpose**: each case is a committed PNG bar chart (`vision/img/`); 36 images ≈ 300 KB kept the repo light. Values are printed on the bars (exact read, tol 0.05) |

Rules (SOT §13.1): `heldout.json` is the promotion evidence for the weekly
full run and is never used to tune prompts. After fixing a held-out failure,
bump `VERSION` in the generator to rotate the held-out seed. Nightly smoke
uses the first 2 EN + 1 VI dev cases per task.
